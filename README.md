# 可靠性综合管理系统 · V3.1

**一个 HTML 文件就是全部。** 双击 `test.html`，用 Chrome / Edge 打开就能用——不联网、不装软件、不需要服务器。
数据存在浏览器本地（`localStorage`），随时可以「数据管理 → 导出 `data.json`」备份，或换台电脑导入。

> 适合：一个人或一个小组维护元器件库存、BOM、实验排期和芯片出入库，不搞权限审批那一套。

---

## 30 秒上手

1. **打开**：双击 `test.html`（建议固定在浏览器书签栏）；
2. **录入**：左侧导航选页面，右上角「＋」按钮是各页的新增入口；
3. **备份**：改完数据点「数据管理 → 导出 data.json」，放网盘或共享盘；
4. **换机/恢复**：在新环境打开后「数据管理 → 选择 data.json」导入即可；
5. **芯片库存**：可以直接导入组里在用的两张 Excel 表（见下方「芯片库存」）。

| 编号 | 页面 | 管什么 |
|---|---|---|
| 01 | **元器件台账** | 电容 / 电阻 / 保险丝 / 螺丝 / 散热片等物料的库存、位号、分类；支持拖拽排序、分组折叠 |
| 02 | **BOM** | 每块板的用料和计划板数；顺手算出**本批需求 / 库存 / 缺口**，页面底部汇总全部芯片的采购量并导出清单 |
| 03 | **缺货预警** | 按安全库存筛出不够的物料，按缺口排序，一眼看到要买什么 |
| 04 | **实验看板** | 实验主题 → 准备事项 → 送样 → 投实验 → FT；含设备借还、待办清单、ELFR 排班（可自由填颗数/人数）和实验安排导出 |

## V3.1：早期失效（ELFR）安排更自由 + 看得到每人工作量

### 批次自由填

- **投料数量不再限定 120 / 80**：任何正整数都能录入（80、90、150……都行），新增 / 编辑批次都可以直接改；
- **投实验人数 1–8 人自由填**：批次卡片上的数字框直接改，增删人数时**已填的人名保留**；120 颗去 2 人、80 颗去 3 人都可以，不再按"120 必 3 人、80 必 2 人"强制；
- **生成建议安排**：仍然优先按 120 / 80 拆批（均衡性最好）；如果总颗数凑不成整批（比如 810 = 6×120 + 90），**余量会单独生成一批**，不再报"无法组成完整批次"。

### 「👥 工作量」小入口

批次列表工具栏最右侧加了一个不太显眼的小按钮 **👥 工作量**，点开是每个人一张表：

| 姓名 | 投实验次数 | FT 次数 | 工作量 |
|---|---|---|---|
| 张三 | 3 | 2 | 8 |
| 李四 | 2 | 3 | 7 |

- 口径：一次投实验 = 2，一次 FT = 1；同一批去几个人，颗数不摊分，按参与次数记；
- 按工作量从高到低排序，底部显示"最高 / 最低 / 差值"，方便自己安排人；
- 只读展示，不影响任何数据。

### 顺手修的漏洞

- **共享目录路径不再写死在代码里**：旧版把内网 UNC 路径（含「★秘密★」字样）写死在 JS 常量里，仓库是公开的，等于泄露内部目录结构。现在只存在本机浏览器：`数据管理 → 设置共享目录` 填一次，「复制数据路径」和导出提示都用它；没设置时只给通用提示，**不会写进 `data.json`，也不会同步给同事**；
- **「重新平衡」不再偷偷改人数**：旧版会把投实验人数夹回 2–3 人，手填 4 人以上点平衡后会被悄悄改掉；现在按 1–8 人原样保留。

### 兼容

`injCount` / `qty` 只是**放宽取值范围**，不是改结构：V3.0 及更早导出的 `data.json` 照常导入；导出版本号变为 `3.1`。

## V3.0：芯片库存（出入库 + 组内库存）

### 两张 Excel 表分别是什么

| 工作表 | 含义 | 关键列 |
|---|---|---|
| **芯片数量** | 从 **FT 厂** 来的芯片，按包装/批号一条一条登记 | 序号（标签号）、型号、来源、入库日期、批号、包装、入库数量、变动情况（变动记录编号）、现有数量、更新日期、备注 |
| **芯片变动情况** | 给**客户发货 / 送样**的记录 | 记录编号、变动日期、申请人、地区、客户、客户类型、项目、项目需求量、产品型号、样品数量（pcs）、批号、记录人、用途、备注 |

系统里对应成两个子页签：**芯片数量** / **芯片变动情况**，右上角带实时条数。

### 列是怎么对应的

```
芯片数量（第一张表） → 系统
序号·型号·来源·入库日期·批号·包装·入库数量·变动情况(编号)·现有数量·更新日期·备注
                                                        │
                                     "1,2,3" 逗号拆开 → 关联到变动记录

芯片变动情况（第二张表） → 系统
记录编号·变动日期·申请人·地区·客户·客户类型·项目·项目需求量·产品型号·样品数量(pcs)·批号·记录人·用途·备注
```

- **日期**：`2026.02.03` 点格式导入时自动转成标准日期，导出时再写回点格式；
- **表头叫法不同也能认**：`包装入库数量 / 入库数量`、`样品数量 / 变动数量 / 实发数量 / 送样数量`、`项目需求量 / 需求数量 / 需求量` 都支持，认不到精确名会按关键词模糊匹配；
- **导入时会显示「列名识别」**：哪列认成了哪个字段、哪列没找到，一眼可见，不会悄悄导成 0。

### 现有数量怎么算

系统按**统一台账**理解这两张表：

```
现有数量 = 入库数量 + Σ入库变动 − Σ出库变动
```

- 变动记录带 **类型**：**出库**（发样/发货，橙色标）扣数量，**入库**（退样/补货/调增，绿色标）加数量；
- 关联了库存的变动会自动改「现有数量」，编辑或删除记录会**原样回退**；
- 「累计领用」按该批所有**出库**记录的样品数量自动汇总；
- **灰色地带留给你**：现有数量仍然可以手工改（遗失、盘点、对不上账的情况）；
- 手改过的数字如果和"按记录算出来"的不一致，该行会显示 **⚠ 差额** 徽章，鼠标悬停能看到"账面应为多少"；
- **导入时只提醒、不覆盖**：预览底部列出所有对不上的行（"表写 70，按记录算 80"），导入后保留你表里的原值。

### 变动记录的「库存数量」

**不读第二张表**——直接取所关联库存行的**现有数量**。因为你们出货表里本来就没有这一列，而库存量的权威数据在第一张表。

### 标签号（序号）

「序号」是贴在包装上的物理标签号，必须连续且唯一：

- 新增库存时**自动排下一个号**（现有最大号 +1），也可以手动改；
- 手动改撞号会被拦住，并提示建议的号；
- 导入时**保留你表里原来的序号**，不会按行号重排；
- 点库存行的「记录」按钮 → 跳到变动页签并筛选出这一批的全部流水，顶部有「清除筛选」。

### 导入 / 导出

- **导入**：`芯片库存 → 导入 Excel`，选包含两个工作表的 `.xlsx`，先预览条数、列名识别、核对提示，再点「确认导入」；
- 导入是**整体替换**当前两组数据，导入前请先「导出 Excel」或导出 `data.json` 备份；
- **导出**：按你们表的原样生成两个工作表（表头、列顺序一致），可以拿回 Excel 改完再导回来。

### 与旧数据的关系

`chipStocks` / `chipMovements` 是**新增的可选数组**：老版本（V2.4 / V2.5）导出的 `data.json` 导入后自动补空数组，不会报错、不会丢数据。

## V2.5 变更

### 出货与计划解耦

之前「计划板数」和「已出板数」是绑在一起的：已出多少，就必须把计划改到多少才能再出一次货。
现在出货只做两件事——**按 BOM 扣库存、记一条出货记录**，和计划板数完全无关：

- 计划 100、先出 100、再出 100 都可以，不需要改计划（`shipped` 会累计到 200）；
- 每次出货写入 `boards.<底板/HAST板/顶板>.shipments`：`{id, at, qty, note}`；
- BOM 区新增「记录 N」按钮，可查看历史出货、撤销最近一次（库存自动加回，并写一条反向流水）；
- 计划板数只用于「需求核算」，输入框上已标注；计划小于已出不再报错，只把数字标红。

### 需求核算并入「BOM」页

原来的独立「需求核算」页已删除，全部合到 BOM 页：

- 每块板的 BOM 表直接多出 **单板 / 本批需求 / 库存 / 缺口** 四列，改完计划板数立刻重算；
- 页面底部是 **全部芯片的需求汇总**，带「导出采购清单」；
- 需求 = 计划板数 × BOM 单板用量，再和当前库存比较，**不扣减历史出货**；
- 出完 100 块后计划照旧写 100，汇总仍然显示 200 的需求，不需要把上次的数量加上去。

### 缺料也能出货

以前库存不足会直接拦住整单。现在改成先算清楚、再由你决定：

| 选择 | 结果 |
|---|---|
| 取消 | 本次不出货，**所有库存原样不动** |
| 确定（强制出货） | 够的物料正常扣；不够的物料扣到 0，缺多少记进这次出货记录 |

弹出确认框会逐条列出：`物料 A：需要 200，库存 150，缺 50`。
出货记录里会标「缺料 N 种」，撤销最近一次时只加回**实际扣掉**的数量。

### 实验设备登记（独立于资产台账）

实验要用的设备不一定是台账里的资产，可能是组里共用的、隔壁实验室借的、临时买的，所以**在实验卡片里单独记**，不引用资产编号：

- 每张卡片可登记若干设备：名称 / 状态 / 应还日期 / 备注；
- 状态三档：**待准备 → 实验中 → 已归还**；
- 应还日期**选填**，填了才会标逾期，不填就只当记录；
- 实验标记「已FT」但还有设备没归还 → 卡片红色提示，同时进「待执行事项」；
- 复制试验主题时，新卡片的设备重置为「待准备」，不继承上一轮的借还状态。

「资产设备」页保持原样，两边互不影响。

### 实验安排导出

- 「导出实验安排」**一次导出全部主题**（准备事项 + 投实验 + FT），文件名 `实验安排_全部主题_日期.xlsx`，用「实验主题」列区分；
- 不再给每张实验自动塞一行「实验概况」：有 ELFR 分批的实验只导出真实的投实验 / FT 工作项；没有分批的实验导出一条阶段安排（送样 / 实验 / 结项）；
- **执行人只有一列**，填的是谁就写谁；不再区分「计划执行人 / 实际执行人」，也不再自动标注「执行人与原计划不同」；
- **准备事项带优先级 1 / 2 / 3**（1 最优先，默认 2）：准备面板按优先级排序，导出表有「优先级」列，同一主题的准备项按优先级 → 计划日期排序（表格 18 列）；
- 总览页也有「导出实验安排」入口，不用先切进某个主题。

### ELFR 排班：按「投实验 2、FT 1」均衡

- 工作量按**参与次数**算：一次投实验 = 2 个单位，一次 FT = 1 个单位（不再按颗数折算）。
  120 颗去 3 人、80 颗去 2 人，人均都是 40 颗，所以两种批次的一次参与算同样的工作量，不乘批次系数；
- 生成建议安排时，同等负载的人之间随机挑，**每次生成结果不同**，但每人总工作量之差不超过一次投实验；
- 手工改过的名字会被记住并锁定，点「⚖️ 重新平衡」只重排没锁定的名额；
- 平衡只在「草案批次」（待准备、无投实验日期、无 FT 记录）内进行，已开始/已完成的批次原样保留。

### 实验代码

- 实验项可填**代码版本**和**简要说明**（都选填）；
- 填了以后卡片上会显示一行「实验代码 v1.2.3 · 说明」；
- 两个字段可缺省，2.4 / 2.5 导出的 `data.json` 导入后自动补空串，旧数据不受影响。

### 待办把准备、送样、设备放在一条线上

- 「待执行事项」上移到「实验准备」面板**之前**，不用滚到下面才看见；
- 状态为「待准备」且有「送样时间」的卡片，自动按送样日期生成待办，不再依赖手填「下一步日期」；
- 设备未归还、设备逾期会生成「设备借还」类待办，实验做完也不会漏掉归还。

### 其它顺手改动

- **BOM 单板用量可以直接改**：表里「单板」那一格就是输入框，改完回车立即重算本批需求与缺口，不用再「删了重加」；
- **出货前就知道缺不缺**：输入板数时，弹窗里实时显示「库存充足」或「N 种物料不足 + 各缺多少」；
- **实验卡片快速更新**：卡片底部「快速更新」只填 状态 / 当前进展 / 下一步 / 日期 四项，「全部编辑」仍是完整表单。ELFR 卡片的状态由分批记录推导，不在这里改；
- **「＋ 新增试验项」挪到卡片列表上方**，和「试验项与执行进展」标题同一行；
- **台账拖拽排序与分组折叠**：「拖拽排序」进入平铺模式拖动行即可调整顺序，顺序会落盘；分组行点击或按 Enter / 空格可折叠，折叠状态存在 `localStorage` 的独立键里，不写进 `data.json`。

## 数据兼容

`data.json` 只做加法，不做破坏性变更：

- **V2.4 / V2.5 导出的备份可直接导入 V3.0**，缺失的新字段全部自动补默认值；
- `chipStocks` / `chipMovements` / `devices` / `shipments` / `codeVersion` / `codeNote` / `injectorLocked` / `testerLocked` / `priority` 都是可选字段；
- 读：字段缺失补默认，脏数据（非数组、混入 null）会被过滤；
- 写：导出的 `version` 为 `3.0`，`material` / `test` 两部分结构与旧版一致；
- 仓库里有 2.4 差分测试（`review/test-compat-diff.js`），验证新旧解析结果除新增字段外逐字段一致。

## 浏览器要求

- `DecompressionStream`（Excel 导入）与 CSS `:has()`：Chrome / Edge 105+；
- 通过 `file://` 打开时，浏览器的「自动加载 data.json」会被安全策略拦掉，请用「数据管理 → 选择 data.json」或直接把文件拖进页面。
